# Project Instructions

## Git

### コミットメッセージ

- コミットメッセージは [Conventional Commits](https://www.conventionalcommits.org/) 形式（`<type>: <subject>`）で記述する。
- subject（件名）と body（本文）は**日本語**で、エンドユーザーが読んでも変更内容が分かるように書く。
  - 内部実装の説明（関数名・ファイル名・リファクタ手順など）ではなく、ユーザーから見た変化を主語にする。
  - 例: `feat: VRChat 起動状態をステータスバーに表示`

### type とリリースノートの対応

コミットメッセージはリリースノートに転記されるため、type の選択と件名の書き方はそれを前提にする。

| type | リリースノート上の分類 |
| --- | --- |
| `feat` | 新機能 |
| `fix` | 不具合修正 |
| `perf` / `refactor` | 改善 |

- `feat`: ユーザーが新たに利用できるようになった機能を書く。
- `fix`: どのような不具合が解消されたかを書く（例: `fix: ログイン後にフレンド一覧が表示されない問題を修正`）。
- `perf` / `refactor`: ユーザーが体感できる改善点（速度・安定性など）を書く。
- 上記以外の type（`chore`, `docs`, `ci`, `test`, `style` など）はリリースノートに載らない想定なので、ユーザー向けの変更を含む場合は上記の type を使う。
